# Module 2 Phase B-1: Ingestion UI + File Storage

⚠️ **Medium** — Multiple new components (frontend page, backend endpoints, database schema, Supabase Storage) but each task is well-defined.

## Goal

Build the document ingestion interface: a drag-and-drop file upload page, Supabase Storage for file persistence, a `documents` table to track uploaded files and their processing status, and backend endpoints for upload/list/delete.

> [!NOTE]
> This plan covers **only** the ingestion UI and file storage layer. Chunking, embeddings, and pgvector come in the next step (line 34).

---

## Proposed Changes

### 1. Database — `documents` Table

Track uploaded documents with processing status for realtime UI updates.

```sql
create table public.documents (
    id uuid default gen_random_uuid() primary key,
    user_id uuid not null references auth.users(id),
    filename text not null,
    file_type text,             -- MIME type
    file_size bigint,           -- bytes
    storage_path text not null, -- path in Supabase Storage bucket
    status text not null default 'uploaded'
        check (status in ('uploaded', 'processing', 'ready', 'error')),
    error_message text,
    chunk_count integer default 0,
    created_at timestamptz default now(),
    updated_at timestamptz default now()
);

alter table public.documents enable row level security;
create policy "Users can view own documents" on public.documents
    for select using (user_id = auth.uid());
create policy "Users can insert own documents" on public.documents
    for insert with check (user_id = auth.uid());
create policy "Users can delete own documents" on public.documents
    for delete using (user_id = auth.uid());
create policy "Users can update own documents" on public.documents
    for update using (user_id = auth.uid());
```

Enable Realtime on the `documents` table for live status updates.

**Validation:** Check table exists, RLS policies are active, Realtime is enabled.

### 2. Supabase Storage — `documents` Bucket

Create a `documents` bucket scoped by user ID. Files stored as `{user_id}/{document_id}/{filename}`.

```sql
insert into storage.buckets (id, name, public) values ('documents', 'documents', false);

-- RLS: users can only access their own files
create policy "Users can upload documents" on storage.objects
    for insert to authenticated with check (bucket_id = 'documents' and (storage.foldername(name))[1] = (select auth.uid()::text));
create policy "Users can view own documents" on storage.objects
    for select to authenticated using (bucket_id = 'documents' and (storage.foldername(name))[1] = (select auth.uid()::text));
create policy "Users can delete own documents" on storage.objects
    for delete to authenticated using (bucket_id = 'documents' and (storage.foldername(name))[1] = (select auth.uid()::text));
```

**Validation:** Upload a test file via API, verify it's stored and retrievable.

### 3. Backend — Document Router (`routers/documents.py`) [NEW]

Endpoints:
- `POST /api/documents/upload` — Accept multipart file, store in Supabase Storage, insert `documents` row
- `GET /api/documents` — List all documents for the authenticated user
- `DELETE /api/documents/{doc_id}` — Delete document + storage file

**Validation:** Upload, list, and delete via `curl`.

### 5. Frontend — Navigation + Page Structure

The app currently has no routing — it renders `ChatPage` directly when authenticated. We need a simple tab/view switcher to toggle between **Chat** and **Documents**.

#### [MODIFY] `App.tsx`
Add a simple view state (`'chat' | 'documents'`) and a nav bar to switch between views. No need for react-router — a state-based approach keeps it simple.

#### [NEW] `IngestionPage.tsx`
Main documents page with:
- Drag-and-drop upload zone (with click-to-browse fallback)
- File type badges (PDF, DOCX, MD, etc.)
- Document list table showing: filename, type, size, status, date, delete button
- Status badges with colors: `uploaded` (blue), `processing` (amber), `ready` (green), `error` (red)
- Empty state with upload prompt

#### [NEW] `FileUploadZone.tsx`
Reusable drag-and-drop component:
- Dashed border drop zone with icon
- Drag-over visual feedback (highlight border, change background)
- Accepts: `.pdf`, `.docx`, `.md`, `.html`, `.txt`
- Shows upload progress per file
- Calls the backend upload endpoint

**Validation:** Browser test — drag a file, see it upload, appear in the list with "uploaded" status.
