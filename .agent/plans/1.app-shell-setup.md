### 3. Supabase — Auth + Database

#### Schema (via Supabase MCP or dashboard)

No custom tables are strictly needed for Module 1 — the OpenAI Responses API manages threads and messages server-side. However, we need a lightweight mapping table so users only see their own threads:

```sql
CREATE TABLE user_threads (
  id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
  user_id UUID NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  thread_id TEXT NOT NULL,  -- OpenAI thread ID
  title TEXT DEFAULT 'New Chat',
  created_at TIMESTAMPTZ DEFAULT now()
);

ALTER TABLE user_threads ENABLE ROW LEVEL SECURITY;

CREATE POLICY "Users can only see their own threads"
  ON user_threads FOR SELECT
  USING (auth.uid() = user_id);

CREATE POLICY "Users can insert their own threads"
  ON user_threads FOR INSERT
  WITH CHECK (auth.uid() = user_id);

CREATE POLICY "Users can delete their own threads"
  ON user_threads FOR DELETE
  USING (auth.uid() = user_id);

CREATE POLICY "Users can update their own threads"
  ON user_threads FOR UPDATE
  USING (auth.uid() = user_id);
```
