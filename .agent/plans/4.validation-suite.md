# Module Validation: Comprehensive Test Suite

✅ **Simple** — This plan outlines a standardized, repeatable test suite that AI agents or human developers can run to verify that all existing features in the Agentic RAG Library are functioning correctly and no regressions have been introduced.

## Goal
Establish a clear suite of end-to-end tests covering all features built across Modules 1, 2A, 2B-1, and the recent Settings/OpenRouter enhancements. Each test includes step-by-step instructions and strict acceptance criteria.

## Features Currently Implemented

Based on `PRD.md` and the `.agent/plans/` directory, the following features are actively deployed:

1. **Authentication & App Shell (Module 1)**
   - Supabase Email/Password Auth.
   - Secure routing between `AuthPage` and main app (`ChatPage`/`IngestionPage`).
   - Row-Level Security (RLS) ensuring users only see their own data.

2. **Thread & Memory Management (Module 2A)**
   - CRUD operations for Chat Threads saving to Supabase `user_threads`.
   - Message persistence saving to Supabase `chat_messages`.
   - Auto-generation of thread titles based on the first user message.

3. **Provider Abstraction & Settings**
   - Universal `/api/chat` endpoint supporting multiple providers via `base_url` overrides.
   - SSE Streaming of LLM responses.
   - Dynamic error handling bubbling up backend provider errors (e.g., 429 Rate Limit) to the frontend.
   - Settings UI for specifying custom OpenRouter API keys, adding custom models, and changing the active LLM.

4. **Document Ingestion UI & Storage (Module 2B-1)**
   - Navigation between "Chat" and "Documents" views.
   - Drag-and-drop file upload zone.
   - File persistence to Supabase Storage (`documents` bucket).
   - Document metadata tracking in Supabase `documents` table with real-time UI status updates.

### Test 1: Authentication & Navigation
**Steps:**
1. Navigate to `http://localhost:5173`.
2. Ensure the login fields are cleared, then enter the test credentials.
3. Click "Login" (Not Sign Up).
4. Verify you are redirected to the main app interface.
5. Click "Sign Out". 
6. Verify redirect back to the Auth page. Sign back in for the remaining tests.

**Acceptance Criteria:**
- Output logs and network tab show successful 200 OK for Supabase auth endpoints.
- UI gracefully handles login/logout state without requiring a manual page refresh.

### Test 2: Chat Thread Lifecycle
**Steps:**
1. Click "New Chat" in the sidebar.
2. Send a short, generic message (e.g., "Hello, say 'Test Passed'").
3. Wait for the streaming response to complete.
4. Verify the UI updates the Thread Title automatically from "New Chat" to a relevant short phrase.
5. Send a second message and verify it appends to the same thread.
6. Click "New Chat" again, verifying the UI clears the message history for the new thread.
7. Click the first thread in the sidebar to switch back, verifying the previous messages load.
8. Click the trash/delete icon on the test thread.

**Acceptance Criteria:**
- Messages stream properly via SSE without hanging.
- Thread titles auto-generate correctly.
- Switching threads accurately restores persisted message history from the backend.
- Deleting a thread removes it from the UI immediately.

### Test 3: Provider Abstraction & Settings
**Steps:**
1. Open the "Settings" modal.
2. Enter the test OpenRouter API key into the corresponding field.
3. In the "Add Custom Model" input, type a test model: `google/gemma-2-9b-it:free` and click "Add".
4. Set the "Chat Model" dropdown to use `google/gemma-2-9b-it:free (Custom)`.
5. Close the settings modal.
6. Start a new chat and send: "What model architecture are you?"
7. Wait for the response or error.

**Acceptance Criteria:**
- The custom model successfully appears in the dropdown list and persists.
- The chat request successfully targets the OpenRouter API.
- If the model is available, a streamed response generates.
- If the model is rate-limited or policy-restricted (common with free OpenRouter tiers), the UI MUST explicitly display the error (e.g., "Error: Provider returned error... 429..."). It must **not** silently fail or secretly fall back to OpenAI.

### Test 4: Document Ingestion UI & Storage
**Steps:**
1. Navigate to the Documents / Ingestion view.
2. Use an agent tool (or manual drag-and-drop) to upload a dummy text file (e.g., `test.txt` with basic content).
3. Verify the file appears in the document list.
4. Verify the status badge says "uploaded".
5. Click the delete button for the uploaded document.

**Acceptance Criteria:**
- The file upload completes successfully (`POST /api/documents/upload` returns 200).
- Real-time subscription instantly updates the UI to show the document.
- Deleting the document removes it from both the UI and the backend storage.

## Agentic Execution Plan 

When asked to run this test suite, an AI agent should:
1. Ensure both frontend (`npm run dev`) and backend (`uvicorn main:app`) servers are running.
2. Use a `browser_subagent` or Playwright tools to programmatically step through Tests 1-4.
3. Provide a summary artifact detailing the Pass/Fail state of each test and any stack traces for failed steps.
